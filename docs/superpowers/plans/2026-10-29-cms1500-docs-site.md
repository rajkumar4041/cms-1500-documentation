# cms1500-react Documentation Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a single-page Vite + React + TS documentation site for `cms1500-react` that recreates the reference site's look and embeds the real library for live, editable PDF demos.

**Architecture:** One long page composed of section components under a sticky mono-nav sidebar, a hero, and `.demo` cards (live panel + code pane). Visual language is ported verbatim from the reference stylesheet. Live demos drive the real `cms1500-react@^1.3.0` via its `useCMS1500` hook with debounced regeneration into an iframe. Dark-first theme with a `localStorage`-persisted light toggle. Static deploy to Vercel.

**Tech Stack:** Vite, React 18, TypeScript, `cms1500-react@^1.3.0`, `pdf-lib`, Vitest + @testing-library/react (logic units only).

**Spec:** `docs/superpowers/specs/2026-10-29-cms1500-docs-site-design.md`

## Global Constraints

- Stack is Vite + React + TypeScript; deploy target is Vercel (static SPA).
- Depend on `cms1500-react@^1.3.0` and its peer `pdf-lib`; install both from npm.
- Reference stylesheet to port from verbatim: `docs/superpowers/reference/reference-site.css`. Reuse its exact design tokens and class names (`.layout`, `.sidebar`, `.hero`, `.demo`, `.demo-body`, `.demo-live`, `.demo-code-pane`, `.code-block`, `.tok-*`, `.pill`, `.btn`, `.install`, `.topbar`, `.icon-btn`, `.toast`, `.menu-toggle`).
- Dark theme default; light via `data-theme="light"` on `<html>`, persisted to `localStorage` key `cms1500-docs-theme`. Only the theme flag may be persisted — never claim data (zero-PHI stance).
- Demos run fully client-side: no network calls, no persistence of claim data. Sample claim data must be obviously synthetic.
- Content is derived faithfully from the library README (`/home/ttpl-lnve16-0365/cms1500-react/README.md`).

## Review Focus

- **Rapid edits in the live demo** → debounced regeneration must cancel in-flight work; the latest edit wins and no stale PDF is shown. (Task 6 tests the debounce hook.)
- **Invalid/empty field in the live form** (e.g. cleared charge, bad date) → demo shows a status/error state, never a crash or blank white iframe. (Task 6.)
- **Copy-to-clipboard where `navigator.clipboard` is unavailable** (insecure context / older browser) → copy fails gracefully with a toast, no uncaught rejection. (Task 4.)
- **Light theme across every surface** → code-pane token colors and panels remain legible; no dark-only hardcoded colors. (Task 2 / self-check at Task 7.)
- **Narrow viewport ≤900px** → sidebar becomes a drawer, demo bodies stack to one column, no horizontal overflow. (Task 3.)
